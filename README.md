# HOOD_MAN_PROJECT

Python과 pico2d로 구현한 2D 횡스크롤 액션 게임입니다. 개발 명세는 [PRD.md](PRD.md), 단계별 기록은 [DEVELOPMENT.md](DEVELOPMENT.md), 검증 결과는 [TESTING.md](TESTING.md)를 참고하세요.

## 실행 환경

- Windows 64비트
- 확인한 버전: Python 3.13.15, pico2d 1.5.1
- 1280×720 창, 60 FPS 렌더링 목표, 120Hz 고정 물리 갱신

## 설치와 실행 (PowerShell)

프로젝트 폴더에서 실행합니다. Python이 없다면 Python 3.13 64비트를 먼저 설치합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

리소스는 소스 파일 위치를 기준으로 읽으므로 다른 작업 폴더에서 `main.py`의 전체 경로로 실행해도 됩니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| 좌우 방향키 | 걷기 |
| 왼쪽/오른쪽 Shift + 방향키 | 가속하여 달리기 |
| Space | 점프, 공중에서 다시 누르면 이단 점프 |
| Q W E R A S D F | 전투 시트 1~8행 공격 |
| H 유지 | 바라보는 쪽 공격 완전 방어, 놓으면 해제 |
| 상단 숫자 / 숫자패드 1~9 | 해당 수만큼 적 소환, 각 적의 등장 방향은 무작위 좌우 |
| N | 현재 맵의 스테이지 이동 화살표 표시 |
| F5 | 플레이·피격·사망 중 처음부터 다시 시작 |
| 창 닫기 | 종료 |

적은 **숫자 1~9를 누를 때 그 수만큼 맵 양 끝 중 무작위 위치에서 등장**합니다. 예를 들어 3을 누르면 3명, 놓았다가 5를 누르면 5명이 추가됩니다. 각 적의 방향을 따로 뽑으므로 한쪽에 몰릴 수도 있습니다. 자동 생성은 없고 0은 생성하지 않습니다. 숫자를 길게 누르면 추가 소환되지 않습니다. 주인공 HP는 500이고, 적의 유효 공격마다 20씩 감소합니다. HP가 0이면 쓰러지면서 반경 160px 이내의 가까운 적들만 바깥쪽으로 밀어냅니다. 멀리 있는 적은 제자리에서 대기합니다.

- 걷기는 300px/s, 달리기는 720px/s입니다. 방향키 해제·방향 전환·Shift 해제에 강한 제동을 적용하여 미끄러짐을 줄였습니다.
- 일반 두 번째 점프는 600→850px/s, 달리기 두 번째 점프는 780→1000px/s로 강화했습니다. 적에게 둘러싸이면 방향키를 유지하면서 Space를 빠르게 두 번 눌러 넘어가세요. Shift도 유지하면 더 멀리 뛰어넘습니다.
- 좌우 동시 입력은 중립으로 처리합니다. Space·공격 키·F5를 길게 눌러도 동작이 반복되지 않습니다. H는 누르는 동안 방어합니다.
- 피격 중에는 이동·점프를 잠시 제한합니다. 점프 중 피격되어도 중력은 계속 적용됩니다.
- 여러 적의 공격은 각각 20 피해를 줍니다. 2명이 동시에 맞히면 40, 4명이면 80이 감소하며 피격 모션 중에도 다른 공격의 피해가 적용됩니다. 같은 적의 같은 공격은 한 번만 피해를 줍니다.
- 적은 수평 거리가 360px 이상 벌어지면 전체 생성 순서별 360·420·480·540px/s를 순환 배정한 속도로 달려옵니다. 220px 이내로 따라오면 120px/s 걷기로 돌아오며, 두 거리 사이에서는 기존 추격 모드를 유지합니다.
- 창 포커스를 잃으면 눌린 키를 해제하여 이동이 고정되는 현상을 방지합니다.
- F5는 첫 스테이지로 돌아와 HP·위치·두 맵의 적·누적 소환 수·화살표·카메라·효과·입력을 초기화합니다. 다시 숫자를 누르기 전에는 적이 나오지 않습니다. 사망 중에는 적을 소환할 수 없습니다. R은 공격 전용입니다.

전투 키는 Q 왼발 앞차기 / W 오른발 강한 앞차기 / E 왼손 잽 / R 오른손 스트레이트 / A 왼손 훅 / S 오른손 훅 / D 어퍼컷 / F 카운터 / H 블로킹입니다.

적은 HP 200이며 머리 위의 작은 빨간 HP바로 표시합니다. **W는 30, D는 50, F는 40, 나머지 공격은 20 피해**를 줍니다. 유효 타격 구간에 앞쪽 적이 있어야 맞으며, 같은 공격은 각 적에게 한 번만 적용됩니다. HP 0인 적은 쓰러진 뒤 공격하거나 이동을 막지 않습니다.

공격 속도는 **12→18 FPS(1.5배)**로 빨라졌으며 한 동작은 약 0.444초입니다. 주인공 공격이 적에게 적중할 때도 **카메라 흔들림**이 발생합니다. 양쪽의 실제 피해에는 제공된 `blood_hit` 효과가 나타납니다.

**H를 누르고 있으면 바라보는 쪽의 공격을 피해 없이 방어**합니다. 왼쪽을 보며 방어하면 왼쪽 공격은 막지만 오른쪽 공격에는 정상 피해 20을 받습니다. 방어 자세와 방향은 유지되며 H를 놓으면 즉시 해제됩니다. 방향을 바꾸려면 H를 놓고 새 방향으로 다시 방어하세요. 뒤쪽에서 맞으면 피격 상태가 되며 H를 계속 유지하면 피격 모션 종료 후 다시 방어합니다. 방어한 공격에는 혈흔·피격 흔들림이 발생하지 않습니다. F5로 방어와 효과까지 초기화됩니다.

## 스테이지 이동

1. 첫 맵 `newStage.png`에서 **N**을 누르면 맵 맨 오른쪽에 노란 오른쪽 화살표가 나타납니다.
2. 오른쪽 끝으로 이동하면 `newStage-2.png`의 왼쪽에서 이어집니다.
3. 두 번째 맵에서 **N을 놓았다가 다시 누르면** 양쪽 끝에 화살표가 나타납니다. 왼쪽 끝으로 이동하면 첫 맵 오른쪽으로 돌아옵니다.

전환 중에도 **걷기·달리기 속도, 점프 높이·상승/하강 속도·남은 점프 횟수, HP와 애니메이션 진행 상태**를 이어갑니다. 방향키·Shift·Space를 유지해도 입력이 끊기지 않습니다. 맵마다 소환한 적의 체력·효과·소환 순서·N 표시 상태는 보존하며, 떠난 맵의 시뮬레이션은 일시 정지합니다.

두 번째 맵의 오른쪽 화살표는 **다음 스테이지 준비 중** 표식입니다. 현재는 두 맵을 왕복합니다. 화면 오른쪽 위에서 현재 스테이지 번호를 확인할 수 있습니다.

## 개발 검증

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe tools/prepare_assets.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py --smoke-test 120
.\.venv\Scripts\python.exe tools/check_render.py
.\.venv\Scripts\python.exe tools/check_runtime.py
.\.venv\Scripts\python.exe tools/check_stages.py
```

원본 PNG를 보존하며 `assets/frames.json`에 프레임별 클립 좌표를 생성합니다. 생성된 파일이 저장소에 포함되어 있어 일반 실행에는 Pillow가 필요하지 않습니다. 스모크 테스트는 실제 pico2d 창에서 지정한 프레임을 렌더링하고 정상 종료합니다.

`check_render.py`는 주요 상태의 실제 렌더링 화면을 `artifacts/`에 저장합니다. `check_runtime.py`는 SDL 키 이벤트·HP바 픽셀·창 포커스·재시작·정상 종료를 검사하고 적 4명 상황의 FPS를 출력합니다. `check_stages.py`는 N 표시 픽셀·배경 전환·양방향 걷기/달리기/공중 이단 점프·맵별 객체 보존·마지막 표식·F5를 실제 SDL 입력으로 검증합니다.

## 코드 구성과 조정

| 파일 | 역할 |
| --- | --- |
| `main.py`, `game.py` | 캔버스·SDL 입력·게임 루프·렌더링·종료 |
| `world.py` | 고정 시간 시뮬레이션·스테이지 왕복·플레이어 상태 연속성·사망·재시작 |
| `player.py`, `controls.py`, `physics.py` | 이동·점프·공격·블로킹·피격·사망·입력·물리 |
| `combat.py`, `effects.py` | 전투 행·피해·범위 정의와 blood_hit 프레임·수명 |
| `enemy.py`, `spawn_manager.py`, `collision.py` | 적 HP·피격·사망·추적·공격·넉백·숫자별 무작위 좌우 생성·충돌 |
| `assets.py`, `animation.py` | 이미지·Windows 기본 맑은 고딕 로딩, 프레임 재생 |
| `stage.py`, `camera.py`, `ui.py` | 맵별 객체·배경·N 이동 화살표·카메라·스테이지/HP UI |
| `config.py` | 이동 속도·중력·피해·넉백·스폰·애니메이션 조정값 |

원본 PNG는 프로젝트 루트에 유지합니다. 주인공·적 기본 시트는 2048×1536의 8열×6행, BasicCombat은 2048×2304의 8열×9행입니다. 시트를 교체하면 `tools/prepare_assets.py`로 총 168개 프레임 클립 정보를 재생성합니다. blood_hit는 1024×512의 4열×2행이며 고정 셀을 순서대로 재생합니다. 캐릭터 원본은 오른쪽을 보며 왼쪽은 수평 반전합니다. 글꼴이 없는 환경에서도 게임과 HP바는 동작하며 텍스트만 생략됩니다.
